# Work-driven source compaction

User-approved direction: every accepted capture is considered by a resumable work queue; wall-clock hours only organize recaps. Preserve authoritative originals and existing consent, power, deletion and signing behavior.

Use the existing encrypted source directory, per-source cursor and four-call worker quantum. Retain an independent encrypted summary block for each admitted source span, atomically with its cursor and block count. There is no whole-source summary byte limit or fixed number of retained blocks. A single local model request consumes one original span and returns its summary plus optional Library proposals. Input spans adapt to actual model/power admission down to a Unicode rune; output reserve respects the provider ceiling. Source completion means every saved byte was visited, not that a head/tail excerpt was selected. Summaries are lossy derived views, never replacements for originals or exact search.

Bind the changed processor to a new model identity suffix so existing completed sources receive one resumable pass. Save each block and cursor together, retain prefixes on refusals, and fence writes against deletion. Existing source-erasure journals drain blocks one transaction at a time using a durable high-water slot count, including stale model generations. Keep compaction running when local background summaries are enabled even if automatic Library proposals are disabled; preserve existing claims in that mode. Proposal capacity must not block source compaction: preserve a visible limited-claims receipt while retaining the span summary and advancing the cursor.

Use all completed source summary blocks for broad recap evidence, explicitly labelled as generated source compactions. If they expand the original or the generation changes during paging, retain raw evidence instead of dropping blocks to meet a made-up source limit. Precise lexical, transcript and document extraction keep raw text. Calendar recaps can still select sources within their context budget; that remains disclosed separately from source-byte coverage. Pending sources rotate and append-ordered capture work progresses alongside legacy history.

Try up to the existing 4 KiB evidence-input protocol size and shrink using actual token admission, rather than capping compaction at the unrelated legacy 1 KiB proposal frame. Preserve exact source-derived technical identifiers outside generated prose when the model omits their names. Summary-only responses may omit the disabled suggestions field; enabled extraction still requires its array.

New durable derivatives require schema 8 so older schema-7 erasure code cannot orphan them. Upgrade authenticated metadata atomically in place, preserving existing payload ciphertext. Verify migration interruption rollback, historical source/note/task/derived data preservation, and authenticated old-reader rejection before recovery mutation.

Verify UTF-8 middle/tail coverage, encrypted reopen, no replay of completed sources, no summary advancement on errors, exact source identity, disabled Library behavior, deletion, and provider request admission. A synthetic native queued check has processed a 19,940-byte ten-agent log in five calls (largest admitted input 4,096 bytes), retaining all ten exact names; this is a smoke/throughput baseline, not a million-record benchmark. No app launch/restart is authorized by this work.
