# Voice archive recall and original authority

Continue the user's authorized personal-memory goal inline on root main. This
is hardening existing voice-note storage, Ask and native source navigation, not
a new recording mode or permission change. Saved originals must remain findable
after the recent window and must not reappear after erasure.

## Approaches and decision

Reuse the existing bounded exact-index windows and scoped browsing, then
authenticate every candidate against the live meeting reverse edge. Extend
committed-read publication through Ask and queued native original reads. This
is the implementer's call within the delegated goal. A larger single storage
query conflicts with unchanged physical limits. Recent catalog sampling alone
cannot locate older topical or explicit historical notes.

## Behavior

Explicit voice-note, transcript and recording requests identify saved recorded
sources, as meeting/call requests already do. A bare browser/video question
retains its two-hour, explicitly unverified association heuristic. Topic queries
use the encrypted source index over their actual scope, split into at most
fifteen 28-day windows for up to400days. Explicit scoped requests without topic
terms browse saved voice sources with the existing aggregate2MiB returned-byte
and context budgets. Unscoped broad latest-note reads can retain bounded recent
catalog selection, with truthful omission coverage. Browser chrome cannot become
spoken content; app/domain identity alone cannot forge meeting membership.

A result-bound token covers all mandatory reads and later native installation.
Voice tokens track committed authenticated meeting-namespace changes separately
from ordinary desktop capture; this volatile constant-space counter changes no
stored schema. Source writes, metadata changes, erasure and closure invalidate
it. The global Search/time guards retain their existing all-write semantics.
Question history conditionally checks that exact scope atomically; its own
write leaves the voice epoch unchanged. It still cannot adopt an intervening
voice mutation as fresh evidence. The callback
installs loaded values only, with no storage IO or waiting for a writer. Native
voice-source lookup and transcript pages also check request, selected note and
Client/durable epochs. Erasure, committed changes, cancellation and mandatory
failures suppress stale output. Existing transcript paging and honest track labels
remain. Authored notes retain distinct provenance.

## Constraints and evidence

Preserve schema7 and all storage/model/recording limits, exact canonical signing,
settings and user memory. No user Blur store reads, app lifecycle actions,
recording, permissions, language downloads, external sends, commit or push.
Tests use temporary encrypted stores and synthetic speech events; no claim of
live microphone/system audio quality or arbitrary-app capture acceptance.

Real-store REDs must prove older voice-note recall, yearly topical and non-topical
recall, late phrases beyond recent pages, genuine source provenance, erased and
forged sources, and queued original/Ask deletion. Runtime histories vary sources,
scopes, utterance positions, competing sessions, erasure and reopen, checking
independent inserted IDs/facts after changes. Counts remain separate from the
older immutable million-target campaign and from semantic uniqueness.
