# Rebuild Blur Around Capability-Based Trust Boundaries

Blur can and should become a first-class macOS, Windows, and Linux product, but **accessibility is a portable product capability, not a portable API**: the shared Go core must ask for capture, selection, replacement, hotkey, overlay, secret-store, and local-transport capabilities while OS adapters implement only what their desktop session can safely provide. The current draft should not enter implementation unchanged because it puts Accessibility capture, the database key, complete memory access, indexing, scheduling, and AI egress in one daemon, fixes a confidentiality-only database format too early, and postpones the highest-risk desktop and packaging work until Tasks 16–23 ([current design](../docs/superpowers/specs/2026-11-04-blur-design.md); [current plan](../docs/superpowers/plans/2026-11-04-blur-full-reimplementation.md)). The recommended target is a small signed platform host that owns OS permissions and emits only bounded, sanitized observations; a key-holding core daemon that owns encrypted storage and deterministic policy; an optional egress broker that alone holds remote-provider credentials; disposable Wails renderers; and stateless, capability-scoped MCP/CLI clients. **SQLCipher should be the production-default storage candidate because it authenticates pages, while ncruces Adiantum should remain an experimental confidentiality-only backend until a cross-OS benchmark and fault gate proves the tradeoff acceptable** ([SQLCipher design](https://www.zetetic.net/sqlcipher/design/); [Adiantum VFS](https://pkg.go.dev/github.com/ncruces/go-sqlite3/vfs/adiantum)). Token efficiency should come from deterministic deduplication, source-preserving retrieval units, hybrid rank fusion, exact token admission, immutable derivation records, and sending diverse source leaves—not from trusting progressively lossy generated summaries. Exact visual and injection parity is impossible, especially on Wayland and across inconsistent accessibility providers, so Blur should promise equivalent workflows plus an honest runtime capability report rather than silent fallbacks. Reordering the plan around early signed platform spikes, fixture apps, authenticated transport/storage, and capture privacy gates will reduce more risk than building the memory and AI layers first.

## Seven changes must land before implementation begins

The draft has strong principles—local-first operation, no screenshots, optional AI, evidence provenance, bounded capture, and visible egress—but several interfaces contradict those principles. Most importantly, `Accessibility.Frontmost() -> WindowSnapshot` permits content to be materialized before `privacy.Filter` decides whether the target should be excluded, even though the prose says exclusions happen before reading. The daemon also combines the two things an attacker most wants—complete plaintext memory and remote-network authority—and one shared install token means compromise of the least-trusted client can collapse all local API authorization. These are architectural, not implementation-level, defects.

A secure/password fixture must fail if any value getter is called, not merely if the final value is absent. |

| **Should-change during the foundation** | Build lifecycle safety before broad features | Implement one restartable two-generation state machine for migration, backup, rekey, compaction, and swap; authenticate the state record; use SQLite Backup API or `VACUUM INTO`; validate, close all handles, fsync, atomically swap, and only then retire the old wrapped key ([SQLite Backup API](https://www.sqlite.org/backup.html)). |
| **Should-change during the foundation** | Establish operability as a content-free contract | Define typed error codes, operation IDs, queue/byte/node counts, duration buckets, capability states, token counts, and per-process SLOs. | **Should-change during the foundation** | Preserve semantic recall without embedding frames | Add deterministic deduplicated session/topic retrieval units between raw observations and generated pages; embed those units locally, fuse FTS and dense candidates with Reciprocal Rank Fusion, and pack only diverse source leaves. | **Defer intentionally** | Risky parity mechanisms | Defer Wayland edge bars, Flatpak capture, Windows UIAccess/elevated automation, secure-desktop interaction, clipboard replacement, generic synthetic-input injection, and gesture variants on backends without release events. Report unsupported capability instead. |
| **Defer intentionally** | Expensive intelligence and scale optimizations | Defer HNSW until exact/quantized cosine misses measured latency targets; defer proactive AI, automatic style learning, broad workflows, compatibility import, and universal updater polish until capture/search/export/deletion are reliable. |

This ranking reconciles an apparent disagreement in the source notes about whether capture belongs in a dedicated helper or the Wails host. The practical first architecture should treat the native Go host and WebView renderer as different trust components: the **native platform host may own capture and surfaces, but the renderer gets only a narrow presentation facade and never receives raw frames**. If signed spikes show that the host cannot provide a sufficiently narrow boundary, extract the same `CaptureSource` implementation into a separately signed `blur-capture` helper without changing the core. This keeps macOS permission ownership understandable—Apple reports Accessibility trust for the process making the AX calls—while preserving an escape hatch for stronger isolation ([Apple `AXIsProcessTrusted`](https://developer.apple.com/documentation/applicationservices/1460720-axisprocesstrusted)).

## Four process planes keep raw text contained

The short recommended target architecture is: **one portable Go domain core; one OS-specific platform-host adapter per desktop family; one authenticated encrypted store; one policy gate in front of every AI request; and capability reports everywhere a platform can degrade**. The native host performs metadata preflight, bounded accessibility reads, secure-field refusal, and first-pass redaction before an ingest-only IPC boundary. The core reapplies current redaction, stores observations, runs deterministic search and jobs, and produces typed evidence. Remote egress is optional and isolated; strict-local mode does not start it. Wails owns dashboard/tray/panel presentation behind `DesktopShell`/`SurfaceManager`, while MCP and CLI remain short-lived, keyless clients.

Encrypted data flow: random DEK → SQLCipher candidate → WAL/temp/backup tests

The core should enter explicit startup states—`booting → locked/no-key → migrating → ready → degraded → draining`—and capture must not start until it has a current, authenticated privacy/exclusion snapshot. Platform callbacks should only enqueue identifiers and timestamps; bounded workers perform reads, because macOS AX can time out, Windows event callbacks can re-enter, and Wayland/portal state can disappear during normal operation ([Apple AXUIElement errors](https://developer.apple.com/documentation/applicationservices/axuielement_h); [Microsoft SetWinEventHook](https://learn.microsoft.com/en-us/windows/desktop/api/winuser/nf-winuser-setwineventhook)). On daemon disconnect, the host may keep only a small already-sanitized memory queue, coalescing or dropping under pressure.

Storage should use a stable random DEK independent of Keychain, DPAPI, or Secret Service. macOS should use non-synchronizing data-protection Keychain items; Windows should wrap the key with DPAPI CurrentUser, never LocalMachine; Linux should distinguish a locked or unavailable Secret Service from a genuinely missing secret and offer an explicit encrypted passphrase-keyfile fallback rather than plaintext ([Apple data-protection Keychain](https://developer.apple.com/documentation/security/ksecusedataprotectionkeychain); [Microsoft DPAPI](https://learn.microsoft.com/en-us/windows/desktop/api/Dpapi/nf-dpapi-cryptprotectdata); [Secret Service specification](https://specifications.freedesktop.org/secret-service/latest-single/)). `NotFound` is the only state allowed to create a new key; `Locked`, `InteractionRequired`, `Unavailable`, `Corrupt`, and `AccessDenied` must fail closed without creating, truncating, or migrating a database.

## Cross-OS parity requires capability negotiation, not emulation

Cross-OS support is viable because all three families expose accessibility semantics, but their safety and completeness differ. Windows TextPattern is read-only, so edits depend on ValuePattern or provider-specific support; AT-SPI exposes `EditableText`, but individual Linux applications may not implement it; and Wayland intentionally withholds global surface position and arbitrary cross-client authority ([Microsoft UI Automation text model](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-understandingtheuiautomationtextobjectmodel); [AT-SPI EditableText](https://gnome.pages.gitlab.gnome.org/at-spi2-core/libatspi/iface.EditableText.html); [Wayland protocol model](https://wayland.freedesktop.org/docs/book/Protocol.html)). Blur should therefore define parity as “capture/search/chat/pause/evidence and safe writing where reported available,” not identical panels or universal injection.

The Windows named-pipe adapter must never accept the default descriptor because Microsoft documents that default pipe ACLs grant read access to Everyone and anonymous users; it should explicitly allow the current user SID, deny network clients, and verify the connected token and logon session ([Microsoft named-pipe security](https://learn.microsoft.com/en-us/windows/win32/ipc/named-pipe-security-and-access-rights)). Linux IPC belongs only in a validated user-owned, mode-0700 `$XDG_RUNTIME_DIR`; macOS and Linux peer credentials strengthen the connection but do not identify user intent, so they supplement rather than replace per-client secrets ([XDG Base Directory specification](https://specifications.freedesktop.org/basedir/0.8/); [Linux `unix(7)`](https://www.man7.org/linux/man-pages/man7/unix.7.html)). All autostart remains visible, per-user, and in the interactive session—never root or SYSTEM.

The inline-writing guarantee in the current plan must be weakened honestly. AX checks and writes are separate cross-process calls, Windows and Linux provider support varies, and no adapter can promise an atomic compare-and-set into a third-party control. A `TargetLease` should retain process/session, application identity, window and accessible-element identity, role/secure state, selection, bounded context hash, and capture generation; Blur should re-resolve and revalidate immediately before writing, refuse unsupported targets, and describe the remaining race. Clipboard and `SendInput`-style fallbacks create global mutable state or stronger automation authority and should remain separately disclosed, opt-in experiments—if shipped at all. Windows `SendInput` also cannot cross higher integrity levels under UIPI ([Microsoft SendInput](https://learn.microsoft.com/windows/win32/api/winuser/nf-winuser-sendinput)).

## Deterministic evidence cuts tokens and injection risk

The current “embed chronicles/wiki only” approach saves indexing tokens but can permanently lose paraphrased details that no generated summary preserved. A more efficient three-tier index keeps **Tier A** raw, deduplicated observations in weighted FTS5; **Tier B** deterministic session/topic windows made from unique source hashes with FTS plus one local embedding; and **Tier C** chronicles, facts, user notes, and wiki views. Queries should parse time/app/domain/entity/exact-phrase constraints deterministically, search relevant tiers in parallel, fuse independent lists with RRF, apply recency only when the query implies it, suppress duplicates, optionally rerank only the top 20–50 candidates locally, expand chosen units to exact source observations, and pack evidence by marginal coverage per serialized token. SQLite FTS5 already provides Unicode tokenization, phrases, prefixes, BM25, weighted columns, and snippets; a separate trigram index should be reserved for identifiers/substrings rather than replacing word search ([SQLite FTS5](https://www.sqlite.org/fts5.html)).

This architecture minimizes both model tokens and information loss. Exact/quantized cosine over vectors stored inside authenticated SQLite is a maintainable first implementation; HNSW should be a rebuildable encrypted cache only if benchmarks require it. Remote embedding is a separate, high-volume egress feature because it can disclose a large share of memory during indexing; it requires explicit opt-in, an initial-volume estimate, per-source exclusions, and its own daily/monthly budget. Before tuning thresholds, the project needs a versioned offline harness that measures recall@k, MRR/nDCG, temporal-filter correctness, entity collisions, citation coverage, deleted/stale leakage, packed evidence tokens, latency, and indexing cost at 100k and 1M observations. BEIR supports keeping BM25 as a robust baseline while treating reranking and late interaction as higher-cost optional tiers ([BEIR](https://arxiv.org/abs/2104.08663)).

Every generated artifact should be an immutable materialized view with direct input IDs/hashes, processor/schema/prompt/redaction versions, provider/model digest, decoding settings, output hash, source coverage, omissions, token/latency usage, and typed claim-to-source edges. Deterministic code—not a model—owns source selection, rank fusion, byte/token packing, identity merge decisions, fact state, citations, authorization, and activation. Models may compress language or propose facts/aliases, but model-derived text remains `model_derived_untrusted` and can never become `policy_control`; persistent memory is itself an injection source, not trusted context. Removing dangerous sinks is more reliable than delimiters alone: memory jobs and Q&A receive no provider-routing, settings, filesystem, network, secret, or mutation tools, and every evidence ID in structured output is validated. OpenAI similarly frames agent risk as the conjunction of untrusted sources and dangerous sinks ([OpenAI agent security](https://openai.com/index/designing-agents-to-resist-prompt-injection/)).

Provider handling should record capability evidence rather than infer it from “OpenAI-compatible.” `ModelDescriptor` needs immutable model revision/digest where available, context/output limits, schema subset, streaming/cancellation, embedding dimensions and prefixes, reranking, exact token counting, cache telemetry, locality (`in_process`, `loopback`, `private_network`, `remote`), origin, credential reference, retention declaration, and evidence provenance (`declared`, `discovered`, `probed`, `user_override`). A separate admission engine authorizes the final serialized request and returns a receipt with request/period budgets and decision reason. Strict-local HTTP must disable proxies, pin resolution to dial, validate every redirect, reject non-loopback addresses before bytes are written, and distinguish a loopback daemon from proof that computation stays on-device. Automatic fallback can remain within one egress class and grant; crossing to remote always requires a new visible authorization.

Token accounting should distinguish `exact_preflight`, `local_tokenizer`, `provider_estimate`, and `conservative_bytes`, reserve output before input packing, reconcile estimates with reported usage, and separate interactive from background budgets. Prompt construction should put stable policy/schema/examples before user profile and dynamic evidence, but Blur must distinguish three caches: immutable local artifacts, narrowly allowed snapshot-bound local responses, and provider-specific KV-cache hints/telemetry. This avoids accidentally treating a provider cache as a durable result cache or caching time-relative chat.

MCP should shrink from 16 overlapping tools to six evidence-oriented defaults—`search_memory`, `get_sources`, `get_activity`, `get_entity`, `get_chronicle`, and `get_time_report`—with optional grant-enabled packs. Every result needs a versioned envelope containing `request_id`, stable snapshot/high-watermark, bounded items, authenticated opaque cursor, truncation/omission counts, bytes, warnings, raw-vs-generated labels, provenance revision, and stale state. MCP calls must never trigger remote AI or unbounded materialization; semantic search is allowed only through an already loaded local embedder and explicit grant. MCP's specification explicitly requires access control, input validation, rate limiting, output sanitization, and schema-conformant structured results, while tool annotations remain untrusted hints ([MCP tool security](https://modelcontextprotocol.io/specification/2026-07-28/server/tools#security-considerations)).

## Reorder twenty-four tasks around platform risk

The current plan defers the Wails shell to Task 16, focused-text/hotkey work to Task 18, dictation to Task 20, and packaging/update recovery to Task 23. That sequence allows months of storage and AI work before proving the app can capture safely, keep focus, survive permission changes, package on Windows/Linux, or roll back an operationally broken build. The following order preserves the full destination while placing irreversible format and desktop decisions behind evidence.

| Revised phase | Reordered work from the current plan | Exit gate |
|---|---|---|
| **0. Contracts, threat model, and feasibility** | Task 1; replace Task 2 contracts; pull a minimal Task 16 shell, Task 18 target spike, and Task 23 signed-development packaging forward; add SQLCipher-vs-Adiantum and process-boundary spikes | Minimal shell runs on macOS, Windows, GNOME/KDE; capability report is visible; native fixtures prove secure controls are never read; panel/palette and target-lease limitations are documented; storage backend and package/update channels have decision records |
| **1. Secure offline foundation** | Rework Tasks 3, 5, 6, 7, 8, and 9 for `SecretStore`, `PrivatePath`, `LocalTransport`, two-phase capture, per-client grants, platform host/core split, and all three OS adapters | No raw sentinel crosses the first process boundary; encrypted WAL/temp behavior passes tamper/crash tests; renderer loss does not stop capture; permission loss degrades only the affected capability; no unbounded call or queue |
| **2. | **5. The design document should be amended concretely rather than patched with a “cross-platform later” sentence. In **Status/Intent/Goals**, replace “initial platform macOS” with capability-based Tier 1 targets and state that release timing may be staggered while all adapters and fixtures remain in-tree. In **Non-goals**, remove Windows/Linux exclusion and add non-goals for identical edge placement, elevated/secure-desktop automation, and silent synthetic-input fallback. In **System architecture/Process model**, replace the monolithic capture daemon with the process/data-flow above and make strict-local deployment omit the remote provider broker. In **Technology choices**, pin an exact Wails patch, introduce `DesktopShell` and `EncryptedStore`, and make SQLCipher the authenticated default candidate behind a measured gate; do not enable Wails private macOS APIs merely for translucency.

In **Platform/Capture**, replace `Accessibility` and `WindowSnapshot` with the capability contracts and staged raw/sanitized types, per-target timeouts/circuit breakers, ingest-only grants, and a capture host independent of JavaScript readiness. In **Storage**, add KEK/DEK separation, typed secret-store states, authenticated generations, hostile import isolation, `synchronous=FULL` as the durability default unless benchmarks justify disclosure, and an honest deletion vocabulary: removed from active views, compacted/rekeyed from the active managed store, and not guaranteed absent from OS/user backups or SSD remnants. SQLite documents that WAL is persistent database state and that long-lived readers can prevent checkpoints, so WAL growth and read backpressure require explicit SLOs and fault tests ([SQLite WAL](https://www.sqlite.org/wal.html)).

In **Retrieval/Memory/AI**, add the three tiers, RRF, embedding-space version keys, derivation ledger, durable idempotent job queue, trust classes, capability-specific provider ports, serialized-request admission, no cross-egress fallback, and cache separation. In **MCP/Local API**, replace the global install token and Unix-only assumptions with scoped grants, stable snapshot pagination, reduced tools, `LocalTransport`, and aggregate CPU/bytes/range quotas. In **Threat model/Privacy controls**, document that root/admin/kernel or a fully compromised same-user session is out of scope; redaction is heuristic; a local model server is a separate principal; safe replacement is best effort; and deletion cannot erase Time Machine/APFS/cloud copies or inaccessible SSD cells. NIST explicitly notes that host overwrite cannot reliably reach every flash cell, so “secure delete” must never be marketed as physical erasure ([NIST SP 800-88 Rev. 2](https://csrc.nist.gov/pubs/sp/800/88/r2/final)). In **Performance/Verification/Delivery**, split budgets by platform host, renderer, core, and provider; add OS-specific yet behaviorally comparable SLOs; require signed fixture/release-lab tests; and adopt the reordered phases above.

The tradeoffs are real. Process isolation and per-client grants add IPC, pairing, update, and support complexity, but they sharply reduce accidental authority and make strict-local claims testable. SQLCipher adds native build and reproducible-packaging work, but authenticated pages are a better default for long-lived personal memory than confidentiality-only deterministic encryption. Maintaining three desktop backends slows the first public release, but early shared fixtures prevent a macOS-shaped domain model from hardening into the schema. Local session-unit embeddings add compute and disk, but they avoid repeatedly paying generation tokens and preserve semantic recall that summaries discard. Finally, Wails reduces shell code and now exposes the required macOS panel controls, yet its youth warrants an owned facade, exact pinning, renderer recovery tests, and a measured escape hatch rather than framework types throughout the product.

## Conclusion

The cross-OS question changes Blur's architecture for the better: accessibility differences force the project to express permission, safety, and degradation explicitly instead of hiding them inside one macOS-shaped interface. The durable abstraction is not “Accessibility,” but a chain of narrowly authorized capabilities with evidence about what the current OS, session, and target can actually do.

The most important sequencing insight is that the encrypted schema and AI features are not the foundation—the **privacy-preserving capture boundary, authenticated lifecycle, and platform capability contract are**. Once those are proven on real signed fixtures, the portable Go core, token-efficient retrieval, optional AI, and OSS ecosystem can grow without weakening the user's trust boundary or requiring a later cross-platform rewrite.
